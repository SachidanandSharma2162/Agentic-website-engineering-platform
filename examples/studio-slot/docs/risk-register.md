# Risk register: Studio Slot

| ID | Risk | Severity | Mitigation | Status |
|---|---|---|---|---|
| R1 | Overbooking under concurrent requests | high | One atomic conditional INSERT (capacity check and insert in a single statement) plus a UNIQUE(class, email) constraint; concurrent-request API test | **mitigated**: 16-process race gives exactly 5 winners; same on the Cloudflare runtime (30 requests, 3 runs); test proven to fail without the condition |
| R2 | Timezone and DST errors | high | UTC storage, studio IANA timezone, table-driven tests across DST changes in a DST timezone | **mitigated**: 31 tests in Kolkata (+5:30), New York (both transitions, every half hour swept) and UTC |
| R3 | Admin passphrase guessing or leakage | high | Constant-time compare, rate limit, signed expiring HttpOnly cookie, secret only as a Worker secret, never in code or logs | **mitigated** (constant-time compare, rate limit, signed expiring cookie, fails closed, tests); production secrets not yet set |
| R4 | Insecure access to bookings (IDOR) | high | Cancellation needs class + secret code (hash stored); roster endpoints admin-only; tests for every route | **mitigated**: identical answers for wrong code, wrong class and unknown class; every owner route tested without a session |
| R5 | Personal data (names, emails) exposure or over-retention | high | Store the minimum, retention purge, no export endpoint, no logging of personal data | **mitigated**: tested (retention at 89/91 days, no address stored, hash-only codes); not yet reviewed against the live system |
| R6 | Spam or abuse of booking | medium | Per-IP rate limit, validation, honeypot field, capacity cap bounds the damage; owner can cancel bookings | **mitigated**: tested; real-world spam levels unknown |
| R7 | Free-tier exhaustion (100k requests/day shared, D1 100k writes/day, 10 ms CPU per request) | medium | Estimated load is about 1-2% of limits; hitting a daily limit returns errors, so the schedule page must degrade gracefully; monitor | **open**: usage not yet observed; daily-limit and outage states are implemented and tested |
| R8 | Pages Functions + D1 binding in direct-upload deploys behaves differently from local | medium | `wrangler pages dev` with local D1 in E2E; the deploy mechanism is verified before Gate C; deploy fails closed | **partly mitigated**: the E2E suite passes on `wrangler pages dev` with a local D1; attaching the binding in a direct-upload deploy is still unverified |
| R9 | Deploy needs actions beyond the first site (database, secrets, token scope) | medium | Listed as Gate E items up front; nothing is created before explicit approval | **open**: nothing created yet, by design |
| R10 | Local SQLite semantics differ from production D1 | medium | Same SQL dialect; production smoke runs the real booking and cancel path with a clearly marked test class that is then cancelled | **partly mitigated**: identical SQL passes on real SQLite and local D1; production D1 itself unverified |
| R11 | Vendor lock-in to Cloudflare | low | Thin data-access layer; plain SQL | accepted |
| R12 | A page that waits for data is torn down and loses messages, or writes into a screen already left | medium | Loader keeps previous data while refreshing and cancels stale requests; component and E2E tests | **mitigated** (found by testing) |
| R13 | Focus not moved to the invalid field for keyboard and screen-reader users | medium | Focus moves in an effect after React commits; E2E, 10 of 10 clean loops | **mitigated** (found by testing) |
